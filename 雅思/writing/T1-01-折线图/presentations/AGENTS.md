# 看图演讲练习维护规则

## 用途与适用范围

本目录存放看图说话的英文演讲稿及练习提示。练习情境是用户站在听众面前，借助图表从开场讲到结束。默认产物是 Markdown 演讲稿，不自动制作幻灯片。

遵守上级文件的资料保护、编码和数据准确性要求。本目录的体裁是口头演讲：不机械套用上级针对 IELTS Academic Writing Task 1 的字数、overview、details 或评分要求。作文可作为内容参考，不能只给作文加上问候语便当作演讲稿。

## 默认风格

- 借鉴 TED 式讲述的情境开场、清晰主线、听众互动和有余味的结尾；不冒充 TED 官方演讲，不保证达到某种专业演讲水平。
- 优先使用用户能够理解和练习的自然英语。用具体、简洁的句子表达，不为营造演讲感堆积生词、夸张修辞或空泛道理。
- 保留用户已有的合适表达、个人称呼和练习意图。用户指定其他风格时，以当次要求为准。

## 内容组织

1. **先读资料。** 阅读用户初稿、对应作文和原题图片，核对主题、单位、年份和数值。原图可以在仓库中找到时直接读取，不沿用初稿中“未提供原图”的旧说明。
2. **确定主线。** 围绕一个听众容易理解的问题组织内容。当前题目的“二十年后回到同一个活动中心，哪些变了，哪些没变”是示例，不作为所有题目的固定模板。
3. **设计开场。** 可用简短问题或明确的假想情境邀请观众进入主题；自我介绍自然融入，不必以长篇背景介绍开始。
4. **按关系讲述。** 根据相似趋势、相反走势、规模或排名变化组织内容。避免每条线都重复“First / Next / Finally + 报数”；必要时仍可逐项介绍，但应让听众知道这些信息之间的联系。
5. **选择数据。** 重点使用起终点、转折和支持比较的数据。数字之后给听众解释或理解空间，不把图中每个年份读一遍。
6. **自然收尾。** 回扣开场或核心问题，留下与图表有关的想法或问题，再简短致谢。避免把正文所有数字重新复述一遍，也不强行升华为人生结论。

## 事实与叙述边界

- 演讲感来自组织和表达，不来自捏造。不得编造参与者的故事、心理、活动费用、宣传效果或社会原因。
- 可明确邀请观众“Imagine…”，但不能把想象情境说成用户亲历或图表证实的事实。
- 区分图表展示的变化与尚未知道的原因；提出原因相关的问题时，应让听众知道图表本身没有给出答案。
- 某活动人数减少、另一活动人数增加，不证明同一批人转去了另一活动。
- 零参与人数不直接证明活动尚未开办；不要把参与人数随意改称观众人数、报名人数或独立人数。
- 读图估值用约数；同一稿件各处数值保持一致。倍数、增长量和增长率须区分；排名变化不臆造精确发生日期。
- 若发现作文或初稿中的错误，修改演讲稿时解释修正依据；不顺手覆盖作文或真题文件。

## 稿件结构与练习支持

- 文件默认采用 `C{册号}-Test{测试号}-Task{任务号}.md` 命名。
- 开头注明日期、练习目标、来源链接及 AI 改写稿身份，使用仓库内相对链接嵌入原图。
- 提供完整英文讲稿，使用便于练习的段落或小标题。可以加入少量中文方括号提示，如停顿、看听众或指图，并明确提示不朗读。
- 配套提供简短的修改理由和 Cue Cards：提示卡只保留关键词、关键数字及要讲清的关系，方便脱稿练习。
- 给出可执行的练习方法，例如先看图与提示卡试讲、卡住再查稿、录音检查听众能否跟上和事实是否准确。
- 时长只能作为试讲参考，须结合实际语速和停顿；不把估计时长当成测量结果。不要将讲稿限制为 IELTS 作文的约 200 词。

## 初稿保留与交付

- 对用户初稿进行实质改写时，保留可对照的原稿；本目录默认将新稿置于前面，原稿放在文末清晰标注的“初稿存档”中。
- 存档只调整必要的标题层级，不悄悄改写原句；存档中的错误数值或过时说明须在存档前提示，练习以新版为准。
- 若当前文件已有存档，后续编辑不得反复把整份文件嵌套存档或覆盖最初原稿。重要版本需要另存时，采用明确的版本名并补充相对链接。
- 交付前检查：主线是否清楚、语言是否适合朗读、比较是否有意义、数字是否一致、假想与事实是否分明、原图和资料链接是否有效、UTF-8 是否正常。
- 交付时简述调整思路、查看位置及仍需试讲验证的事项。除非用户明确要求，不自动提交或推送 Git。
